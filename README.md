# 칼바람 증강 Addon

> 라이엇 게임즈와 무관한 팬 제작 도구입니다. League of Legends 및 관련 이미지·데이터는 Riot Games, Inc.의 자산입니다.

**👉 [사용 설명서](사용설명서.md) · [프로그램 받기 (윈도우·맥)](https://github.com/theddack/aram-augment-tool/releases/latest)**

웹: https://theddack.github.io/aram-augment-tool/ (main 에 올리면 `.github/workflows/pages.yml` 이 web/ 폴더를 자동 배포)

칼바람 증강 모드(내부 이름 `KIWI`)의 증강 223개와 상점 아이템을 게임 데이터에서 뽑아,
챔피언 성향 가중치로 **증강 추천 + 시너지 + 아이템 빌드**를 계산하는 로컬 도구. 통계(승률) 없이 수치·설명만 사용한다.

## 프로그램 (맥·윈도우)

`desktop.py` 가 화면을 독립 창(pywebview)으로 띄운다. 항상 위 고정, 데이터 갱신 버튼은 프로그램에서만 보인다.
데이터는 사용자 폴더(맥 `~/Library/Application Support/AramAugment`, 윈도우 `%APPDATA%\AramAugment`)에 두고, 화면 파일은 실행할 때마다 앱 안의 것으로 덮어쓴다.

| OS | 빌드 | 결과 |
|---|---|---|
| 맥 | `./build_mac.sh` | `dist/칼바람증강Addon.app` |
| 릴리스 | `git tag v0.x.y && git push origin v0.x.y` | GitHub Actions 가 윈도우·맥을 빌드해 릴리스에 zip 업로드 |
| 윈도우 | `build_windows.bat` 더블클릭 (Python 3.12 + WebView2 필요) | `dist\칼바람증강Addon\칼바람증강Addon.exe` |

개발 중 실행: `.venv/bin/python desktop.py` (`--debug` 로 개발자 도구)

### 상점 추천 등록 (아이템 세트, `lcu.py`)

롤 클라이언트 로컬 API(LCU, lockfile 인증)로 챔피언이 정해지면 아이템 세트를 등록한다 → 게임 상점 추천 칸에 표시.
- 블록: 🎯 기본 빌드 / 🔥 "○○ 고르면" 최대 3개(첫 증강 🔥·👍 후보 중 빌드가 2개 이상 달라지는 것) / 🎲 변칙. 괄호 안 방향(원딜형·마법사형·탱커형…)은 완성 빌드 아이템으로 판정
- 게임 시작 전에 등록돼야 상점에 반영된다 → 게임 중 고른 증강은 게임 화면 오른쪽 위 '다음 구매'로 안내
- 우리 세트만 uid `aram-augment-tool-` 로 교체, 사용자가 만든 세트는 유지
- LCU 는 라이엇이 서드파티 공식 지원 대상이 아니라고 밝힌 API (블리츠·OP.GG 도 같은 방식으로 사용)
- **미검증**: 실제 롤 클라이언트 (가짜 클라이언트 서버로 등록 흐름·기존 세트 유지만 확인)

### 게임 화면 표시 (윈도우, 창 모드·테두리 없는 창 모드)

`overlay.py`: 롤 게임 창(`League of Legends (TM) Client`) 위치에 투명 창(tkinter)을 겹쳐 그린다.
게임에 끼어들지 않고(다른 창일 뿐) 클릭은 게임으로 통과한다(WS_EX_TRANSPARENT). 게임 창이 맨 앞일 때만 보인다.
- 증강 카드 밑: 왼쪽·가운데·오른쪽 칸에 입력한 증강의 평가와 짧은 이유
- 오른쪽 위: 고른 증강, 다음에 살 아이템
- 위치 기본값은 위키 선택 화면 스크린샷 기준 추정(세로 70%, 카드 간격 25%). 화면의 '위치 맞추기' 슬라이더 + 미리 보기로 조정
- 전체 화면(독점) 모드에서는 보이지 않는다 → 필요하면 Overwolf 로 이전(심사)
- **미검증**: 윈도우 창 찾기·클릭 통과·화면 배율(DPI) 좌표·tkinter 스레드와 pywebview 동시 실행은 윈도우 실제 PC에서 확인 필요

## 화면

- **증강 연계 티어 (S/A/B/C/D)**: 지금까지 고른 증강 기준으로 같은 등급 증강에 배지를 붙인다. 숫자로 평가되는 증강은 같이 골랐을 때의 빌드 가치, 나머지는 효과 종류·조건 점수로 순위 → S 상위 10% · A 20% · B 30% · C 25% · D 15%. 궁합(같이 골랐을 때 가치 − 혼자 골랐을 때 가치)이 +5 이상이면 한 단계 올리고 −5 이하면 내린다. 조건 미충족·손해는 D. 고른 증강이 챔피언 특징을 바꾸면(검을 뽑아라 → 근접) 그 기준으로 다시 판정
- **이번 선택지**: 게임에 뜬 증강 3개를 입력하면 각각의 빌드 가치(실제 숫자)·같은 등급 내 순위·몰빵 빌드와 콤보/DPS/유효 체력 변화를 비교. 칸마다 새로고침 1회 사용 여부를 체크하면, 새로고침을 안 쓴 칸 중 같은 등급 하위 40% 안에 드는 가장 낮은 칸에 '새로고침 권장' 표시
- 챔피언 선택 → 전체 증강 순위(구경용). 챔피언 스킬 특성·증강 조건·고른 증강/아이템과의 시너지 반영
- 증강 최대 4개, 아이템 6칸 직접 선택 (신발은 1개까지). 고른 아이템은 고정하고 빈 칸만 추천
- 추천 빌드 3종: 증강 몰빵 / 균형 / 변칙. 아이템마다 어떤 증강 때문에 골랐는지 표시
- 증강: 칼바람 증강 모드 목록 223개 중 이번 패치 비활성(Enabled=False) 7개 제외 → 216개
- 아이템 종류: 전설 107 / 신발 7 / 증강 보상 4 (22xxxx 강화템, 황금 뒤집개 — 상점 구매 불가라 자동 추천 제외, 직접 선택만 가능)
- 초기화: 증강 / 아이템 / 전체(증강 + 아이템 + 가중치 + 빌드 탭)

## 챔피언 스킬 특성

Data Dragon 챔피언 상세(패시브 + 스킬 4개 설명)에서 뽑는다.
- 특성 태그: 증강과 같은 분류기. 아군 대상 회복·보호막이 있으면 1.0, 자기 회복만 있으면 0.4
- 피해 유형 비율: 스킬 설명의 마법/물리 피해 표기 수 → 공격/마법 성향에 반반 반영
- 스킬 특징(증강 조건용): 돌진, 밀어내기, 지형 생성, 회전, 소환, 정신 집중, 은신, 이동 불가 CC, 아군 지원, 근접/원거리

## 증강 특수 규칙 (`rules.json`)

자동 분류로 못 잡는 증강 80여 개를 직접 정의했다. 수정 후 `python3 build_data.py` 를 다시 실행하면 반영된다.
- `tags`: 효과 태그 덮어쓰기 · `requires`: 챔피언 스킬 조건 · `items`: 연계 아이템(퀘스트·업그레이드)
- `convert`: 스탯 환산(적응형 능력치 = 공격력→주문력) · `zero`: 빌드에서 무시할 태그(유리 대포 = 체력) · `generic`: 범용

## 공식

- 챔피언 가중치: Data Dragon 역할군(Marksman, Mage …) 프리셋 + `info.attack/magic` 비율 + `info.defense`. 화면에서 슬라이더로 조정 가능.
- 증강/아이템 효과 태그: 툴팁 마크업(`<scaleAP>`, `<healing>` …)과 한글 키워드로 분류.
- 점수식은 화면의 "공식 (가중치) 조정"과 `web/scoring.js` 상단 상수에 있다.

## 능력치 계산 (`web/stats.js`)

- 기본 능력치: 레벨 성장식 `기본 + 성장 × (L-1) × (0.7025 + 0.0175 × (L-1))`
- 아이템: 설명의 능력치 줄 22종 파싱 + 능력치를 바꾸는 고유 효과 4종(`rules.json` items: 라바돈·대천사·워모그·해신 작쇼)
- 아이템 고유 효과: CommunityDragon `items.cdtb.bin.json` 의 수치·계산식 + 문자열 테이블 설명. 모드 전용 수치는 Kiwi(칼바람 증강) → ARAM 순으로 덮어씀
- 챔피언 패시브: 챔피언 bin 의 패시브 스펠 설명(`Buff_*_Tooltip`)과 수치
- 증강: `rules.json` stats (게임 데이터 값 이름으로 연결, 38개)
- 칼바람 보정: 가하는 피해·받는 피해·회복·보호막·스킬 가속·공격 속도
- 지표: 스킬 콤보(Q·W·E·R 각 1회, 방어력 80·마법 저항력 60 대상, 관통력 적용), 평타 DPS, 유효 체력, 회복·보호막
- 스킬 랭크: 궁극기 6/11/16, 기본 스킬은 Q→W→E 균등 배분으로 가정

## 모드 전용 스킬 수치 (게임 파일)

챔피언 스킬 데이터의 `DataValuesModeOverride`(값)와 해시 칸의 모드별 `Calculations`(계산식)를 Kiwi(칼바람 증강) → ARAM 순으로 적용한다.
- 값 덮어쓰기 36명 63개 스킬 (예: 바드 미프 주문력 계수 50% → 67%, 패치 26.20 노트와 일치)
- 계산식 덮어쓰기 4개 (가렌·리 신·스웨인·신드라 패시브. 가렌 패시브 회복 2~12% 패치 노트와 일치)
- 재사용 대기시간의 모드 조정은 정적 데이터에 없어서(서버 적용) 위키 증강 모드 표의 'Cooldown changed to …'로 반영 (가렌 W·크산테 W·스카너 E·쓰레쉬 W)

## 증강 실제 숫자 평가 (빌드 가치)

- 대상: 216개 중 77개 = 능력치 증강 38개(rules.json stats) + 피해·보호막·회복 효과를 게임 데이터에서 뽑은 증강 42개(겹침 3)
- 효과 종류: 설명의 마크업 태그, 없으면 자리표시자 뒤 문구('의 적응형 피해', '의 보호막', '만큼 체력을 회복')
- 발동 빈도(설명 문구): N번째 기본 공격마다 / N초마다·재사용 대기시간 N초 / 처치·사망·체력 기준·'다음' 기본 공격 → 1회 / 기본 공격 시 / 스킬 사용 시
- 조건(rules.json requires)을 못 맞추는 챔피언은 효과 0
- 빌드 가치 = 지금 균형 빌드(완성 6칸, 18레벨)에 증강을 더했을 때 Σ 지표 가중치 × (지표 변화 / 기준값) × 100
- 나머지 139개(무적·CC·쿨 반환·상대 최대 체력 % 피해 등)는 '숫자 없음'으로 표시하고 순위에서 뺀다

## 한계 (미검증·미해결)

- 스킬 수치 못 채운 자리 77개 (중첩 수·게임 중 계산값 등). 대상 체력 % 피해, 소환물 피해는 콤보에 안 들어감
- 아이템 고유 효과는 118개 중 42개만 피해·보호막·회복 수치로 계산된다. 나머지(이동 속도·둔화·쿨 감소·조건부 버프 등)는 태그 점수로만 반영
- 챔피언 패시브는 168명 설명을 수치로 채웠고, 그중 87명의 피해·보호막·회복이 계산에 들어간다. 중첩·변신 같은 패시브는 미반영
- 발동 빈도는 설명 문구에서 판정한 근사값이다 (충전 공격은 평타 8회에 1번, 콤보 시간 4초 가정)
- 상대 체력 비례 피해는 상대 최대 체력 3000, 현재 체력 70% 가정
- 스킬 콤보는 Q·W·E·R 각 1회 가정. 다단 히트·지속 시간 피해(초당 피해)는 1회분만 셈
- 기준 대상(방어력 80·마법 저항력 60)은 고정값이라 실제 상대 조합과 다르다
- 칼바람 보정: 위키 기준 '일반 칼바람 보정 + 증강 모드 전용 보정(59명)'을 덮어써서 쓴다. 위키 표 기준 시점이 25.17로 적혀 있어 최신 패치와 다를 수 있다

- 스킬 특징 정규식은 표본 확인만 했다 (전 챔피언 검수 아님). 예: 소환 특징은 9명만 잡힌다.
- `rules.json` 은 설명 문구를 읽고 작성한 판단이며 실제 게임에서 검증하지 않았다.
- 증강 41개는 효과 태그를 못 뽑아(그중 상당수는 rules.json 으로 보완) 기본 점수(0.25)로 처리된다 → 화면에 "효과 분류 안 됨" 표시.
- 증강 15개는 수치 일부가 `?` (게임 데이터의 미해석 계산식). "게임 중 집계"는 플레이 중 누적값이라 원래 숫자가 없다.
- 계산식의 능력치 번호(mStat)는 확인된 8종만 이름을 붙였고 나머지는 "추가 능력치"로 표시된다.
- **증강 수치는 점수에 쓰지 않는다.** 증강은 효과 종류(태그)만 반영하고, 화면의 수치는 설명용이다. 아이템은 스탯 수치를 기준값 대비 크기로 반영한다.
- 추천 결과를 실제 게임 결과와 대조하지 않았다.
